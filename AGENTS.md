# Names That Remain — спільний контекст

Одиночна 2D тактична RPG. Гільдія в похмурому фентезі з надією. Godot 4.7, GDScript, локально, без мережі.

Один репозиторій. Кілька незалежних сесій читають цей файл і `.cursor/rules/`. Кожна сесія працює лише у своїй частині.

## Що читати перед зміною гри

- `docs/GDD.md` визначає ігровий дизайн. Статуси: **[ЗАТВЕРДЖЕНО]**, **[РОБОЧА ПРОПОЗИЦІЯ]**, **[ВІДКРИТЕ ПИТАННЯ]**. Пропозиція не стає правилом без явної згоди.
- `docs/TECHNICAL_DESIGN.md` визначає технічну архітектуру.
- `docs/ARCHITECTURE.md` фіксує контракти між модулями. Їх змінює лише Core і лише після погодження.
- `docs/TASKS.md` показує поточний етап і хто вже може працювати.

## Сесії

| Сесія | Відповідальність | Зараз |
|---|---|---|
| Core / Architecture | Спільні моделі, контракти, інтеграція | Працює першою |
| Combat | Бої та здібності | Лише після погоджених контрактів |
| UI | Сцени та анімації | Лише після погоджених контрактів |
| Checker / QA | Незалежні тести і перевірка | Після результатів Combat і UI. Код гри не змінює |
| Systems | Герої та експедиції | Не запускати |

Паралельно Combat і UI стартують тільки після погодження спільних контрактів. Checker перевіряє обидва результати. Core інтегрує зміни. До першого робочого бою не створювати інші системи і не розкривати сотні файлів.

Ролі викликаються як `/core`, `/combat`, `/ui`, `/checker`. Їхні межі: `.cursor/agents/` і `docs/agents/`. Шляхи `src/` і `content/` не використовуються. Паралельна робота лише після погодженого контракту і без спільних файлів. Git worktrees не створюй без окремого дозволу.

## Правила кожної сесії

- Працювати тільки в межах призначеного завдання і дозволених файлів.
- Не вигадувати нові механіки, класи, характеристики або архітектуру без погодження.
- Розділяти ігрову логіку та візуальні сцени Godot. UI надсилає команди і показує вже пораховані події.
- Писати типізований GDScript.
- Не змінювати спільні контракти без погодження Core.
- Додавати і запускати тести своєї частини. Checker перевіряє, не переписує реалізацію.
- Не заявляти про успішну перевірку, якщо вона фактично не виконувалася.
- Код і технічні ідентифікатори писати англійською. Звіти користувачу писати виключно українською.
- Щойно користувач погодив рішення, запиши його в той самий хід у відповідний документ. Не залишай домовленість лише в чаті.
- Якщо код зручніше змінити, ніж затверджену механіку, зупинись і назви суперечність.
- `.tres` зберігає визначення. Прогрес кампанії живе окремо.
- Гіт, коміт і пуш — лише після явного дозволу.
- Не додавай сервер, акаунти, мультиплеєр і Steamworks.

## Поточний крок

Мінімальний проєкт відкривається в Godot і запускає `scenes/main/main.tscn` з назвою гри. Ігрової логіки немає. Core ще має погодити інтерфейси бою. До цього Combat, UI і Systems не починають реалізацію. До Milestone 1 не переходити без окремого дозволу.
